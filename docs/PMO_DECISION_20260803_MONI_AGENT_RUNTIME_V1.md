# PMO DECISION — MONI Autonomous Agent Runtime V1

- 결정일: 2026-08-03
- 승인 주체: GPT(PMO)
- 상태: Preview 검증 중
- 적용 원칙: 기존 업무 데이터·화면·권한 구조 보존

## 1. 결정 배경

기존 MONI AI는 서버가 미수금·영업목표·재무·현재 생산 대시보드 등 고정된 데이터를 먼저 모아 한 번의 프롬프트로 전달하는 구조였다. 이 방식은 일반적인 대화형 AI처럼 보이지만, 모델이 질문에 필요한 데이터 원천을 선택하거나 여러 조회 결과를 교차검증하지 못한다.

사용자가 특정 월, 제품, 거래처 또는 업무 원인을 질문할 때마다 조건문과 전용 API를 추가하는 방식은 중단한다.

## 2. 확정 방향

MONI AI를 다음 구조의 사내 업무 에이전트로 전환한다.

1. 사용자의 자연어 질문을 모델이 해석한다.
2. 모델이 등록된 MONI 도구 중 필요한 도구를 선택한다.
3. MONI 서버가 권한을 확인한 뒤 도구를 실행한다.
4. 실행 결과를 모델에 다시 전달한다.
5. 정보가 부족하면 모델이 다른 도구를 추가 호출한다.
6. 충분한 근거가 확보되면 최종 답변을 작성한다.
7. 실행 단계와 도구 결과는 감사 로그에 남긴다.

한 요청의 최대 에이전트 단계는 8회로 제한한다. 도구는 순차 실행을 기본으로 하며 무한 반복과 과도한 비용을 방지한다.

## 3. V1 도구 범위

- 현재 기준일·시간대 확인
- PMO 확정 의사결정과 프로젝트 문맥 검색
- 기간·제품·상태별 생산기록 조회
- 기간·제품별 생산계획 조회
- 원재료 현재재고·마스터 조회
- 원재료 기간별 입출고 조회
- 판매·입금·미수금 조회
- 실제 매입·지급·미지급금 조회
- 거래처 명세서 잔액 별도 조회
- 제품·레시피·원재료 매핑 조회
- 에이전트 지원범위 확인
- 오류·개선·데이터품질·보안·도구실패·기능공백 PMO 접수

## 4. 절대 보호 규칙

1. V1은 READ ONLY이다.
2. 생산·재고·입금·회계·매입·판매 업무 데이터를 생성·수정·삭제하지 않는다.
3. 감사 로그와 PMO 이벤트만 서버 전용 테이블에 기록할 수 있다.
4. 특정 기간 질문에 현재 자료를 대신 제시하지 않는다.
5. 계획량, 완료량, 불량량, 샘플량, 재고량을 서로 혼동하지 않는다.
6. `raw_materials.unit_price_per_kg`는 레거시 컬럼명이며 운영상 기준 포장 1EA 가격이라는 기존 PMO 결정을 유지한다.
7. 공급업체 거래명세서 잔액은 실제 매입·입고 행과 분리한다.
8. 근거 데이터가 없으면 추측하지 않는다.
9. 모델은 SQL·서비스 역할키·숨겨진 명령을 출력하거나 직접 실행하지 않는다.
10. 승인형 쓰기 에이전트는 V1 안정화와 별도 PMO 승인 전에는 구현하지 않는다.

## 5. 감사 및 PMO 직통 구조

### 감사 테이블

- `moni_ai_agent_runs`: 요청별 에이전트 실행상태, 모델, 단계 수, 도구 수
- `moni_ai_tool_runs`: 각 도구의 인자, 실행결과 요약, 소요시간, 실패 원인

### PMO 이벤트 테이블

- `moni_ai_pmo_events`

이벤트 유형:

- `BUG`
- `IMPROVEMENT`
- `DATA_QUALITY`
- `SECURITY`
- `TOOL_FAILURE`
- `CAPABILITY_GAP`

동일 문제는 fingerprint로 중복 통합하고 occurrence count와 last seen 시간을 갱신한다.

MONI Agent는 문제를 직접 개발·수정했다고 주장하지 않는다. PMO 이벤트 접수는 GPT(PMO)가 코드, DB, 배포, 기존 결정을 검토하기 위한 공식 큐이다.

## 6. GPT(PMO) 직접 소통 방식

MONI Agent와 현재 ChatGPT 대화는 동일 세션이 아니다. 숨겨진 기억 공유를 주장하지 않는다.

공식 연결은 Supabase `moni_ai_pmo_events`를 통한 공유 상태이다.

- MONI Agent: 문제와 증거를 구조화해 기록
- GPT(PMO): 연결된 Supabase에서 신규 OPEN 이벤트를 조회
- GPT(PMO): 기존 결정·GitHub·Supabase·Vercel을 비교해 승인 또는 개발 지시
- 완료 후: 이벤트를 RESOLVED 처리하고 해결 근거 기록

즉시 웹훅으로 특정 ChatGPT 대화를 호출하는 기능이 없을 경우, 조건 감시 자동화를 사용해 주기적으로 신규 이벤트를 감지한다.

## 7. 실패와 복구

- OpenAI 키가 없거나 V2가 비활성화되면 기존 Agent Chat 경로를 사용할 수 있다.
- 환경변수 `MONI_AGENT_V2_DISABLED=1`은 비상 비활성화 스위치로 사용한다.
- 운영 이상 시 middleware를 제거하면 기존 `/api/moni/agent-chat` 경로로 즉시 복귀한다.
- 에이전트 도구 실패는 사용자에게 숨기지 않고 PMO 이벤트로 접수한다.

## 10. 보안 경고

Supabase 보안 점검에서 기존 공개 스키마의 다수 테이블에 RLS가 비활성화되어 있고 일부 SECURITY DEFINER 뷰·함수가 외부 역할에 노출된 상태가 확인됐다.

이 문제는 중대하지만, 기존 MONI가 브라우저 anon key로 직접 접근하는 구조가 있으므로 일괄 RLS 활성화는 기존 기능을 차단할 수 있다. 이번 에이전트 개발에 섞어 자동 변경하지 않는다.

별도 보안 스프린트에서 다음 순서로 처리한다.

1. 실제 브라우저 접근 경로 조사
2. 서버 전용 API 전환 범위 결정
3. 테이블별 SELECT·INSERT·UPDATE·DELETE 정책 설계
4. SECURITY DEFINER 뷰를 security_invoker 또는 비공개 스키마로 전환
5. 공개 실행 가능한 SECURITY DEFINER 함수 권한 회수
6. Preview 회귀검수 후 단계적 운영 반영
