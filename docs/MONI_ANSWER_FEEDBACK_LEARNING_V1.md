# MONI Answer Feedback Learning V1

## 목적

MONI 답변 하단의 명시적 사용자 평가를 장기적인 품질 개선 증거로 사용한다.

## 신호 강도

- `👍 UP`: 사용자가 직접 해당 답변을 좋은 답변으로 표시한 강한 긍정 신호다.
- `👎 DOWN`: 사용자가 직접 해당 답변을 개선이 필요한 답변으로 표시한 강한 부정 신호다.
- 평가 취소: 기존 라벨을 제거한다.
- 복사 / 공유 / 보고서 다운로드: 편의 기능 사용 신호일 뿐 답변 품질의 긍정·부정 증거로 사용하지 않는다.
- 무응답: 성공 증거로 간주하지 않는다.

## 저장 원칙

각 평가는 `business_id + assistant_message_id + actor_login_id` 조합당 한 건만 유지한다. 같은 사용자가 평가를 바꾸면 새 행을 쌓지 않고 기존 행을 갱신한다.

원본 대화는 `moni_ai_messages`에 보존하고, 평가 라벨은 `moni_ai_answer_feedback`에 분리 저장한다. 운영·생산·재무 업무 데이터와 섞지 않는다.

## 학습 승격 정책

사용자 평가를 받은 답변을 즉시 모델 가중치나 전역 프롬프트에 주입하지 않는다.

1. 사용자 명시 평가를 `CANDIDATE` 증거로 저장한다.
2. 동일 유형의 성공·실패를 의미 기준으로 중복 제거한다.
3. 실제 Agent run / tool run / 오류 기록과 함께 검증한다.
4. 재사용 가능한 규칙 또는 대표 예시만 GPT(PMO)가 검토한다.
5. 승인된 항목만 `PMO_VERIFIED`로 승격한다.
6. 전역 MONI 규칙이 필요하면 기존 `moni_ai_project_context`에 압축된 핵심 규칙 하나로 반영하고 회귀 테스트를 함께 둔다.

따라서 👍가 많다는 이유만으로 자동으로 사실이 되지 않고, 👎 한 번만으로 기존 확정 규칙을 폐기하지 않는다. 품질 라벨은 판단 증거이며 최종 승인권은 GPT(PMO)에 있다.

## UI 원칙

각 MONI assistant 답변 바로 아래에 다음 순서로 배치한다.

`좋아요 · 싫어요 · 복사 · 공유 · 보고서`

좋아요/싫어요는 한 번에 하나만 선택할 수 있고 다시 누르면 평가가 취소된다. 보고서는 해당 답변과 바로 앞 사용자 요청을 서버에서 다시 조회하여 DOCX 업무 보고서로 생성한다. 클라이언트가 임의로 전달한 답변 본문을 보고서 원문으로 신뢰하지 않는다.
