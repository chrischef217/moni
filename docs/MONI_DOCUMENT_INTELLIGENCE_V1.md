# MONI DOCUMENT INTELLIGENCE V1

## 목적
MONI 모바일 채팅에서 사용자가 보고서·PDF·거래명세표 같은 업무 문서를 요청했을 때, 단순 텍스트 안내가 아니라 실제 다운로드 가능한 문서를 제공한다.

## PMO 기준
1. 사용자에게 내부 도구명, DB 컬럼명, 영문 내부 지표를 노출하지 않는다.
2. `PDF로 만들어줘` 요청은 기능 거절 문구를 답변하지 않고 실제 PDF 다운로드 링크를 제공한다.
3. 문서 내용은 저장된 MONI 대화와 공식 업무 데이터를 기준으로 생성한다.
4. 거래명세표처럼 MONI에 이미 공식 양식이 있는 문서는 새 임의 양식을 우선하지 않는다. 기존 거래 데이터와 공식 양식 경로를 우선 사용한다.
5. 거래를 하나로 특정할 수 없으면 임의 선택하지 않는다. 최근 후보를 제시하고 사용자가 특정하도록 한다.
6. 문서 생성 자체는 읽기 전용이다. 생산·재고·매출·매입 등 업무 원장을 문서 생성을 이유로 수정하지 않는다.
7. 쓰기 업무는 기존 prepare → confirmation → execute 승인 경계를 그대로 유지한다.

## 현재 지원

### 일반 MONI 답변 → PDF
- 사용자가 PDF 파일 생성을 명시하면 서버가 저장된 사용자 질문과 MONI 답변을 조회한다.
- A4 PDF를 실제 생성한다.
- 채팅 답변에 인증된 다운로드 링크를 붙인다.
- Markdown 제목·목록·표를 문서 구조로 렌더링한다.

### 답변 하단 `보고서` 버튼 → DOCX
- 저장된 질문 + 답변을 기준으로 DOCX를 만든다.
- Markdown 표를 문자열로 평탄화하지 않고 실제 Word 표로 생성한다.
- 제목, 요청 영역, 표, 목록, 분석 문단을 분리한다.

### 거래명세표
- 공식 `sales_orders`, `sales_order_items`, `sales_clients`, `company_profile` 데이터를 사용한다.
- 거래명세표 번호 또는 거래처가 정확히 특정되면 PDF 다운로드 링크를 제공한다.
- 수출 거래처럼 기존 MONI 거래명세표 화면이 있는 경우 기존 공식 양식 링크도 함께 제공한다.
- 여러 거래가 후보이면 최근 후보를 보여주고 임의로 하나를 선택하지 않는다.

## 사용자 표시 언어
다음과 같은 내부 값은 사용자 화면에서 자연어로 바꾼다.

- `unaccounted_gap_g` → `계획-완료 차이`
- `open_planned_quantity_g` → `미완료 작업지시 계획량`
- `completed_actual_quantity_g` → `완료 실제 생산량`
- Agent tool name → 실제 의미의 한국어 업무 표현

다운로드 URL 자체는 sanitizer가 훼손하지 않도록 보호한다.

## 향후 확장 원칙
새 문서 유형을 추가할 때는 아래 순서를 따른다.

1. MONI에 기존 공식 양식이 있는지 확인
2. 공식 원장 데이터의 식별자와 문서 대상을 정확히 resolve
3. 대상이 모호하면 질문/후보 선택
4. 서버에서 문서 생성
5. 인증된 다운로드 링크를 채팅으로 반환
6. 회귀 테스트 추가
7. GPT(PMO) 검증 후 Production 반영

임의 문서 생성보다 **공식 양식 재사용 + 공식 데이터 결합**을 우선한다.
